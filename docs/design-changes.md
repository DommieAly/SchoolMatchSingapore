# Design changes (DC register)

Every change to the Lab 2 design (class names, attributes, operations, arrows, dialog-map transitions) gets one row here.
In code the change is marked with a comment `// DC-xx`.

- **Status** is "proposed — pending team approval" until the team accepts the row at a meeting; then write "accepted YYYY-MM-DD".
- **Diagram updated** turns to "yes" when the matching `docs/design/*.drawio` file (and its `.png`) is updated. Do that in the same PR as the code (owner F keeps the diagrams in sync).
- A new change takes the next free number. Never reuse or renumber an id: code comments point to them.

DC-01 to DC-24 were found when the Lab 2 diagrams were checked against the Lab 1 requirements, before any code was written. DC-25 to DC-39 were found while writing the skeleton. DC-40 to DC-69 were found while building the features (round 2, October 2026). DC-70 to DC-73 came from the security review after round 2. DC-74 to DC-76 came from switching to the full 147-school snapshot (3 Oct 2026). DC-77 and DC-78 came from adding the MOE SchoolFinder PSLE ranges and affiliations, DC-79 to DC-81 from checking the Google budget and failure logging, and DC-82 from the review of the MOE data (3 Oct 2026).

## Implementation notes (no diagram change)

These do not change the design. Read them before you write code against these classes.

- **Saving `UserProfile` and `Shortlist`:** `accountId` stays null until the first save, and `getAccountId()` falls back to `account.getAccountId()`. Always create a new one with `repo.save(new Shortlist(account))` (or `new UserProfile(account)`).
- **`SchoolChoice.rank`** is stored in the column `choice_rank`, because `RANK` is an SQL function name. `@OrderBy("rank")` still uses the field name.
- **Collections load eagerly**, because `spring.jpa.open-in-view` is off. `ChoicePlan.choices` and `Shortlist.schoolCodes` use `@Fetch(FetchMode.SELECT)`; otherwise Hibernate refuses to load both lists at once (`MultipleBagFetchException`).
- **`Account` checks:** `username` has `@NotBlank @Size(min = 3, max = 30)` and `email` has `@NotBlank @Size(max = 254)` (DC-45). A bad value throws `ConstraintViolationException` when saved, so controls validate first and show field errors. `toString()` leaves out the password hash and the email. Case-insensitive uniqueness of usernames is enforced by the `username_key` column and its unique key (DC-70).
- **`School.getScoreRange(postingGroup, true)`** falls back to the latest non-affiliated range when the school has no affiliated range for that posting group (the DC-22 rule). `getScoreRange(postingGroup, false)` never returns an affiliated range.
- **`District.boundary: GeoJSON`** is stored as `boundaryGeoJson: String` (the Feature's geometry JSON).
- **`SchoolAttributeFilter` and `FacilityFilterCriteria`** constructors accept any `Collection` where the design says `Set`; passing a `Set` works.
- **Settings added:** `app.datagovsg.api-key` (optional). The test profile blanks the Google keys so a local `.env` never leaks into tests.
- **No settings for entity rules:** the SAFE margin and the facility radius options/default are constants on the entities (DC-20, DC-24), so there is no `app.plan.*` and no `app.facility.radius-*` setting.
- **Stub or live:** a live client is used only when its mode is exactly `live`; any other value, including an empty one, selects the stub. A value other than `stub`/`live` stops start-up with a message, and live Google without `GOOGLE_MAPS_SERVER_KEY` does too.
- **`UserProfile.setPreferredCCAs` / `setPreferredProgrammes`** copy the input before clearing, so passing a profile's own set does not empty it.
- **Settings added in round 2:** `app.recommendation.psle-fit.*`, `app.recommendation.reach-near-margin` (DC-53), `app.transport-filter.max-speed-kmh.*`, `app.transport-filter.max-routed-schools` (DC-57), `app.dataset.curated-dir` (read with `@Value` by `CuratedCsvReader`), `app.external.budget.*` (DC-41), `app.onemap.base-url`, `app.datagovsg.base-url` / `open-api-base-url`, `app.google.routes-base-url` / `places-base-url`, `app.http.connect-timeout` / `read-timeout`, `app.dataset.import-output-dir`, `app.dataset.activate-on-import`.
- **Outside HTTP calls** use the one `RestClient.Builder` bean from `config/RestClientConfig` (JDK HttpClient, 5 s connect / 15 s read). `ArchitectureTest` rule 8: only `boundary.external` (and `config`) uses Spring's HTTP client.
- **Actuator:** only `GET /actuator/health` and `GET /actuator/info` are exposed (no login); every other `/actuator/*` is 404.
- **Ended login sessions** are deleted every `app.session.cleanup-interval` (DC-73).
- **No CSRF tokens:** `SameSite=Lax` on `SM_SESSION` plus the `Origin`/`Referer` check of DC-72 (README, "Login and sessions").
- **Search and map share one filter step:** `boundary.ui.support.SearchFilterPipeline` (not a bean; each UI builds one) builds the filters from `FilterParams`, applies them, drops rejected ones and the travel-time filter when routing is down, and says which were applied. The chips and "N of M schools match your filters" show only applied filters; the others are listed as "Not applied" with a remove link.
- **Location picker keeps unsent forms:** a form marked `data-draft-return="/path"` is copied into the picker's `returnTo` while the user edits it (`static/js/draft-return.js`). `GET /recommendations` reads draft criteria from the query string, and after a failed `POST /recommendations` the picker returns with the submitted criteria.
